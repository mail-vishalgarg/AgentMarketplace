Agent Platform — Forge

Complete system design · Phase plan · 4-person team breakdown

What We're Building

A platform that builds agents — not agents themselves. A user describes an agent in plain English; the platform picks tools, checks connections, writes a config document, and deploys it. One shared runtime reads any config and executes it. Agents are data, not code.

Central rule: When the platform "builds" an agent, it writes a JSON configuration document. One runtime reads that document and assembles the agent. No Python is generated or run per agent.

Agent Config Document (Rule 1)

{
  "schema_version": "1.0",
  "name": "GitHub Issues → Slack Summarizer",
  "model": "claude-sonnet-5",          // latest Sonnet 5 (2026)
  "system_prompt": "You are a productivity assistant...",

  "tools": [
    {
      "mcp_server_id": "uuid-github",   // resolved at runtime — NOT in plaintext config
      "tool_name": "list_issues",
      "classification": "read",
      "require_approval": false          // platform reads this, not the prompt
    },
    {
      "mcp_server_id": "uuid-slack",
      "tool_name": "post_message",
      "classification": "write",
      "require_approval": true           // ← Rule 4: platform enforces, not prompt
    }
  ],

  "graph": {
    "type": "sequential",               // or "coordinator_specialist"
    "interrupt_before": ["post_message"]
  },

  "scores": {                           // Rule 6: deterministic, computed server-side
    "functionality": 82,
    "safety": 91,
    "breakdown": { "tool_coverage": 28, "prompt_quality": 22, "approval_gates": 30, "read_ratio": 11 }
  }
}
The runtime is shared. It reads any agent's config. There is no per-agent Python code. Versioning, publishing, and cross-tenant install all work because the agent is data.

8 Rules — How Each Is Satisfied

RuleHow SatisfiedTest to Pass
1 — Config not code AgentRunner reads agents.config JSONB. No Python generated per agent. Inspect agents table — no code columns anywhere.
2 — No cross-tenant visibility Postgres RLS on every tenant-scoped table. app.current_tenant set per request. Remove app filter in test. Query other tenant's agent by known ID. Must get 0 rows.
3 — Credentials vanish Fernet/KMS encrypt on input. Stored as bytea. Fetched only at tool call time, then GC'd. grep -r "ghp_testtoken" on DB dump + all log files. Must return nothing.
4 — Risky actions need approval tools[].require_approval drives LangGraph interrupt_before. Not the prompt. Remove "ask before posting" from system_prompt. Write tool must still pause.
5 — Publishing strips company publish() sets publisher_tenant_id=NULL, strips server IDs, scrubs PII from prompt. Plant sentinel string in agent config. Publish. Find sentinel in marketplace row? FAIL.
6 — Scores must mean something Deterministic formula from config properties. Publish blocked if func<60 or safety<70. Set a low score agent's scores directly in DB. UI must still show blocked publish button.
7 — Every agent gets an endpoint POST /api/v1/agents/{id}/invoke. Postman Collection download. Cross-tenant → 404. Call with wrong tenant's token. Must get 404 not 403.
8 — Multi-agent system coordinator_specialist graph type. Morning Standup Bot: coordinator + GitHub specialist + Slack specialist. Build it through the platform UI (not hand-coded). Demo shows coordinator routing to both specialists.
